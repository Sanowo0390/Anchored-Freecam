# 1.1.12 検証メモ

対象は、範囲端で本体へ戻される、選択中の手持ちを空表示にしたい、幽体の攻撃で他人のFreecamを解除できる、の3点です。

## コード上の修正根拠

- 1.1.11の `maintainBodyEnvironment()` は範囲外を検出すると保存済みの位置を `session.anchor()` で上書きしていました。予約補正でも範囲外なら本体へ戻す分岐がありました。1.1.12では保存位置を保持し、現在位置・保存位置を使い、どちらも範囲外なら範囲球の境界近くへ投影します。投影先が衝突する場合は内側へ0.25マスずつ確認し、安全な候補がなければその補正は実行しません。通常の境界超過で本体へ置き換える処理を撤去しました。
- `onDamage(EntityDamageEvent)` が `onDamageByEntity` より先に本体を処理できる構造でした。攻撃キャンセルをLOWESTへ移し、一般ダメージハンドラーでも本体処理前に幽体攻撃を再確認します。幽体のProjectileも対象です。通常プレイヤーの攻撃・環境ダメージは既存処理を維持します。
- 手持ちは `sendEquipmentChange(player, HAND, ItemStack.empty())` で本人宛ての表示のみ変更します。実インベントリの退避・削除・書戻しは行いません。毎tick再送し、選択変更・インベントリ画面終了の翌tickには `updateInventory()` 後に現在の手持ちを再び空表示にします。Freecam終了時は実インベントリを再同期します。GSitの内部実装は参照していません。

根拠：1.1.11と1.1.12の `FreecamManager` / `FreecamListener` の差分。

## 自動検証

Java 25、Paper API `26.2.build.129-stable`、Gradle 9.6.1でビルド・モックテストを実行。
追加したテストは、範囲端の現在位置、保存位置の維持、本体移動・範囲縮小、補正先衝突、幽体の直接攻撃・Projectile、通常攻撃の維持、手持ち表示送信、選択変更時の復元順、終了・再開始時の古い表示予約の排除です。

## 実機確認（未実施）

1. 15マスの範囲端へ前後左右・斜め・上下から繰り返し近づく。本体付近へ戻らず境界付近で止まることを確認。
2. 本体が落下中・水流で移動中にも試す。途中で範囲を縮めた場合も確認。
3. アイテムを持って開始し、0～8のホットバースロットを順に変更。選択中だけ空表示、前のスロットは復元、オフハンドと本体装備は維持されることを確認。
4. 手動終了・本体右クリック・本体ダメージ・TPA・ログアウト・プラグイン停止後に実アイテムがそのまま残ることを確認。
5. 2人でFreecamし、一方の幽体から相手の本体を攻撃。相手が継続することを確認。その後、攻撃者のFreecamを終了して同じ本体を攻撃し、通常のダメージ終了が維持されることを確認。

モックテストはクライアントのパケット処理・描画を実行していません。Paper/Purpur、Java/Geyserでの手持ち表示・移動感・実際の症状解消は確認が必要です。
